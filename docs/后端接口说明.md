# 后端接口说明

> 服务入口：`app/backend/main.py`（纯标准库，零第三方依赖；OCR 模块除外）
> 启动：`python -m app.backend.main`（环境变量 `PORT` 默认 80，`DEEPSEEK_API_KEY` 必填才能用 AI 解读）
> 前端与所有接口同源（同一端口），无跨域问题。

## 一、接口一览

| 方法 | 路径 | 说明 | 状态 |
|---|---|---|---|
| GET | `/` | 前端静态页面 | ✅ |
| GET | `/api/health` | 健康检查 → `{"ok": true}` | ✅ |
| POST | `/api/analyze` | OCR 文本 → AI 结构化解读 | ✅ |
| POST | `/api/trace` | 商品信息 → 联网溯源证据链 | ✅ |
| GET | `/api/scan-barcode?code=...` | 条码查询商品 | ✅（内置 4 款示例） |
| POST | `/api/ocr` | 图片 → 识别文字 | ⏳ 等 OCR 模块 |

## 二、POST /api/analyze

**请求**（JSON）：
```json
{
  "ocrText": "配料：水、生牛乳、全脂乳粉、结晶果糖… 产品标准号：GB 7101 生产商：…",
  "name": "可选，商品名",
  "brand": "可选，品牌",
  "category": "可选，品类"
}
```

**响应**：与前端 `mock.js` 商品结构对齐的 `product` 对象：
```json
{
  "id": "analyze-xxxxxxxx",
  "name": "含乳饮料（调制乳类）",
  "brand": "识别结果",
  "spec": "未标注",
  "barcode": "未采集",
  "category": "含乳饮料",
  "verdict": {"level": "caution", "label": "慎买", "why": "…"},
  "keys": [{"l": "糖", "v": "37.5", "u": "g / 瓶", "hi": true}],
  "ingredients": [{"name": "生牛乳", "flag": "green", "role": "奶味", "what": "…", "why": "…", "caution": "…"}],
  "nutrition": [{"name": "能量", "per100": "…", "whole": "…", "nrv": 15, "cm": "…", "hi": true}],
  "equiv": [{"big": "≈ 9 块方糖", "small": "…"}],
  "tricks": [{"claim": "0蔗糖", "ok": false, "edu": false, "truth": "…", "basis": "…"}],
  "pairs": [{"with": "正餐", "why": "…"}],
  "health": [{"tag": "控糖", "level": "risk", "text": "…"}],
  "trace": null,
  "ocrText": "原始识别文本",
  "nameSource": "label",
  "nameConfidence": "high",
  "labelName": {"name": "阿萨姆奶茶", "brand": "统一", "maker": "统一企业（中国）投资有限公司", "source": "field", "evidence": {"name": "阿萨姆奶茶"}}
}
```

**商品名从哪来**（`nameSource`，拍配料表时前端不传 `name`，靠这一层）：

| 值 | 含义 |
|---|---|
| `caller` | 调用方传入（条码库命中 / 用户输入），最高优先 |
| `label` | 包装文字里有明确字段（品名 / 产品名称 / 商品名称） |
| `label-inferred` | 包装文字里没字段，从「配料」之前挑出的最像品名的一行 |
| `model` | 包装上没有可读品名，用模型的判断 |
| `none` | 都没有，标题退到 `品类（按配料判断）` |

`labelName` 是这一层的原始产出（`maker` 来自生产商字段，品牌可能在 `evidence.brand_from_maker` 里标注为推断）。
前端按 `nameSource` 在结果卡上写「品名读自包装 / 品名由 AI 判断 / 照片里没拍到商品名」。

**错误**：`{"error": "AI 解读失败：…"}`
**缓存**：同一 `ocrText` 在进程内缓存 50 条（重复分析秒回）。

## 三、POST /api/trace

**请求**（JSON）：
```json
{
  "name": "商品名", "brand": "品牌", "category": "品类", "spec": "规格",
  "ocrText": "包装文字（用于提取生产商/厂址/标准号）",
  "live": true,
  "narrate": false
}
```
**响应**：`{identity, stages, nodes, gaps, provenance, common_sense, meta, note, compat}`
- `nodes`：六阶段证据链（生产加工/标准检验/品牌方/上游供应商/原料产地/流通上架），每条含 `text/confidence/url/quote`
- `gaps`：查不到的环节 + 下一步建议（**不编造**）
- `provenance`：证据总数

**错误**：`{"error": "溯源失败：…"}`

## 四、GET /api/scan-barcode

**请求**：`?code=6925303730574`
**响应**：
```json
{"found": true, "code": "6925303730574", "source": "builtin", "product": {"id": "milktea", "name": "阿萨姆奶茶 原味", "brand": "统一", "category": "奶茶饮料", "spec": "500 ml / 瓶"}}
```
未收录：`{"found": false, "code": "…", "product": null}`

**查询分层**（依次尝试，命中即回）：
1. `builtin`：内置 4 款示例
2. `openfoodfacts`：本地 OpenFoodFacts 中国离线库
3. `openfoodfacts-live`：OpenFoodFacts 在线（免 key）
4. `barcode-api`：条码服务商直通中国物品编码中心备案库（需环境变量 `TANSHU_KEY`，未配置自动跳过）

## 四·五、POST /api/analyze-barcode（扫码联网解读）

扫码查到商品身份但库里没有配料表时调用。后端联网搜配料表 → 提取 → AI 解读；
搜不到则让 AI 按品牌+品类推断并在结果里明确标注。

**请求**（JSON）：
```json
{"code": "6928808012929", "name": "香蕉味卷式夹心糕点", "brand": "达利园", "category": "饼干糕点", "spec": "200克"}
```

**响应**：与 `/api/analyze` 相同的 product 对象，另加两个字段：
```json
{
  "ingNote": "配料表来自联网检索（example.com），可能与实物包装不同，请以实物为准。",
  "dataSource": {"mode": "web", "url": "…"}
}
```
- `dataSource.mode`：`web`（联网搜到的真实配料表）/ `inferred`（AI 推断，`ingNote` 会说明）
- `ingNote` 前端直接显示在配料区底部（复用 `p.ingNote` 渲染）

**依赖的环境变量**（可选，未配置自动降级）：
- `BOCHA_API_KEY` / `TAVILY_API_KEY`：联网搜索（博查优先）
- 都没配或搜索失败 → 走 `inferred` 推断模式（仍需 `DEEPSEEK_API_KEY`）

## 五、POST /api/ocr（等待接入）

**请求**（JSON）：
```json
{"imageBase64": "纯 base64（无 data: 前缀），JPEG，长边 ≤1600"}
```

**响应**：
```json
{"text": "配料：水、生牛乳、全脂乳粉…", "lowConf": ["低置信词1", "低置信词2"]}
```

**未接入时**：HTTP 501 `{"error": "OCR 模块未接入（app/backend/ocr.py 不存在）"}`

### 给 OCR 负责人的对接契约

只需新建 `app/backend/ocr.py`，实现：

```python
def recognize(image_base64: str) -> dict:
    """image_base64: 纯 base64 字符串（无 data: 前缀），JPEG，长边 ≤1600

    返回：
        {"text": "识别出的完整文字（保留换行）",
         "lowConf": ["不确定的词", ...]}
    """
    ...
```

- **不要改 `main.py` 的路由**：`/api/ocr` 会自动发现并调用这个函数
- 精度优先的实现可以在这里加载任意 OCR 模型（rapidocr / PaddleOCR / VLM 等）
- 服务器运行环境是 Ubuntu 24.04 + Python 3.12，注意依赖安装
- 参考：`python3 -m venv .venv && .venv/bin/pip install rapidocr-onnxruntime`

## 六、错误与约定

- 所有错误响应统一为 `{"error": "中文说明"}`，HTTP 状态码：400 参数错误 / 500 内部错误 / 501 未接入 / 502 上游失败
- 请求体大小限制：见 `main.py` 中 `MAX_BODY`（超过返回 413）
- 溯源/解读结果均标注置信度，**不编造**数字与来源
