## 三、原创声明（匿名版）

本作品由 **DeepEggy 团队（4 人）** 原创完成，全部代码与文案写于官方赛期窗口内（2026-11-20 18:00 起）。

**赛期内（48 小时）从零完成的部分**：

1. **产品设计**：拍照/扫码双入口 → 逐项释义 → 量化折算 → 话术拆穿 → 个性化提醒 → 分享卡片，六段式信息架构与手机竖屏交互、视觉系统（暖纸主题）。
2. **前端**：零构建的纯静态 SPA（`app/frontend/`）——相机取景与条码识别、OCR 核对页、7 个结果 Tab、分享卡片 Canvas 绘制、等待遮罩与中断控制。
3. **后端**：零第三方依赖的 `http.server` 服务（`app/backend/`），12 个 API：`/api/analyze`、`/api/analyze-barcode`、`/api/scan-barcode`、`/api/ocr`、`/api/trace`、`/api/reviews`、`/api/products` 等；条码三级查询（本地库 → OpenFoodFacts 在线 → 编码中心备案），联网搜配料表并做品牌/品类/口味一致性校验。
4. **数据整理**：《配料通俗化解释》208 条词条（含 115 个别名，人工整理 + 复核）；过敏原 35 类（GB 7718-2025 的 14 类核心 + 21 类扩展，含花粉-食物交叉反应）。
5. **自研字段抽取模型**：`label_ner.py`，自写 BIO 标注 + 平均感知机，训练数据为合成银标（非真实照片），指标与局限在开发日志中如实记录。
6. **知识库本地化**：GB 2760-2024 添加剂 642 条 + 使用范围 30,429 条、食品分类 388 类，构建脚本与查询层自写；数据文件在赛期内由构建脚本重跑产出。
7. **今日修复**：发现并修复「扫不同商品都显示同一个商品」的缓存键缺陷（缓存键未包含商品身份），已重新部署并逐款验证。

**数据来源与许可**：GB 2760-2024、GB 7718-2025 为公开国家标准；OpenFoodFacts 数据为 ODbL 许可；其余词条、文案、图标全部自写。

## 四、AI 模型与工具使用说明

| 环节 | 用了什么 | 人工把关 |
|---|---|---|
| **运行时·配料解读** | DeepSeek API（`deepseek-chat`）：逐项解释、营养点评、话术拆穿、过敏原提示 | 提示词写死「数字以文本为准、读不到就写未标注、不编造」；结果标注「解读由 AI 生成」 |
| **运行时·联网搜配料表** | Tavily 搜索 + 自建免费搜索（头条/神马/夸克）→ DeepSeek 从网页正文严格提取 | 要求品牌/品类/口味一致才算匹配；提取不到就明确标注「按同类配方推断」，不冒充真实配料表 |
| **运行时·OCR** | 百度智能云 OCR；本地可选 PaddleOCR-VL | 识别结果先进「核对页」由用户确认，低置信词高亮 |
| **运行时·口碑归纳** | 联网抓公开搜索结果 → DeepSeek 归纳 | 每条评价标注来源，抓不到就明说「网上评价较少」 |
| **开发过程** | AI 编程助手参与代码编写、测试、文档与界面迭代 | 产品方向与取舍由团队决定；关键决策、实测数据、失败记录按小时写在 `docs/开发日志.md` |

**说明**：本作品未使用 Ling-3.1-flash、Ling-3.2 等赛事示例模型，运行时仅调用 DeepSeek；所有 AI 输出均标注或可溯源，不用于代替事实。
