## 2026-11-21 10:26–10:46 · 溯源联网层（阶段二）

先做可行性实测再写代码，**结论几乎都跟直觉相反**，把失败结果一并记下，同学不要再走一遍。

渠道验真（`python -m app.backend.trace_search --verify`，13 个候选源，本机 + ECS 双端一致）：

| 结果 | 源 | 实测 |
|---|---|---|
| 可用 | 百度搜索 SERP | 200 / 约 1.0MB / 每页 6–10 条，中文长查询排序最好 |
| 可用 | Bing `&format=rss` | 200 / 0.3s / 5.6KB / 10 条，无 Cookie 也能拿 |
| 可用 | 国家标准全文公开系统 | 200 / 2s，能取到标准号·名称·类别·状态·发布与实施日期 |
| 可用 | 品牌官网（逐个验） | 达能中国 200 / 284KB → 去标签 19699 字正文 |
| 不可用 | 百度百科 403、GSXT 521、CNCA 521、海关 412、京东验证页、std.samr.gov.cn 前端壳（46KB 只剩 409 字）、DuckDuckGo 超时 |
| 不存在 | 国家农产品质量安全追溯平台 `traces.moa.gov.cn` DNS 直接解析失败 |

三个坑，都是当场翻出来的：

1. **「百度被反爬」是我误判**。裸 `-A Mozilla/5.0` 只回 227B 空壳，补齐 `Accept-Language` + `Accept-Encoding` 后是 1MB 真实结果页。凡是把某源标成 blocked 的，先怀疑自己的请求头。
2. **Bing 的 RSS 端点不做中文长查询**。三个内容完全不同的「元气森林」查询返回逐字节相同的结果集，说明它只按首 token 出泛化页。但换到「脉动」，百度整页是软文、只有 Bing 给出百科企业页。所以检索层是**双引擎合并去重**，谁都不是备胎。
3. **通用搜索不能放热路径当结论来源**。「元气森林 苏打气泡水 生产商 工厂」被网易/抖音软文占满，`厂` 字面匹配还会捞进「灌装机厂家」广告和一道百度文库数学题。因此查询模板去掉品类词，命中还要过企业后缀 + 品牌同现 + UGC 域名黑名单三道闸。

据此否掉了「预先海量抓取」的路线：商品是用户现场拍进来的，离线穷举的分母无穷；真正沉淀下来的是**渠道注册表 + 查询模板 + 品类先验表**，共 3 个数据文件段、几十行，不是几百万行。AI 参与的是构建期选路（已验真状态回写进 `data/trace_channels.json`），运行期只走固定路径。

落地内容：

- `data/trace_channels.json`：渠道注册表（层级/URL 模板/解析器/权重/TTL/实测状态/失败模式）。`status` 全部来自真实请求，未验真的一律 `unverified`，品牌官网白名单里没验过的域名留空串并约定跳过。
- `app/backend/trace_search.py`：纯标准库抓取层（编码兜底 utf-8/gb18030、gzip、SERP 缓存原始 HTML、正文缓存去标签文本、SQLite TTL 缓存、百度 `link?url=` 跳转壳解析成真实出处 URL）。
- `app/backend/trace.py`：`/api/trace` 组装层。OCR 文本正则归一化（SC 号、GB 号、生产商与厂址分字段、配料表截断）→ 六阶段链（原料产地 / 上游供应商 / 生产加工 / 标准检验 / 品牌方 / 流通上架）→ 每条证据带 `channel + url + quote + retrieved_at`。
- **反编造是代码约束不是口号**：`ev()` 里 `proven` 必须有 quote 且有 url（包装直读算第一手，例外）；查不到的阶段进 `gaps` 并写下一步怎么补。`app/tests/test_trace.py` 16 条测试专门钉这条，含「离线不得产生任何联网结论」。
- 零依赖：没装 FastAPI 也能跑 `python -m app.backend.trace --serve`，队友可直接联调。

真实商品回归（联网冷跑 → 缓存热跑）：

- 脉动：5 已证实 / 1 待核验 / 3 品类先验，冷跑 3.5s、热跑 0.3s。标准层顺带查到 `GB 7101-2003 固体饮料卫生标准` 状态为**废止**——这本身就是可展示的产品结论。
- 元气森林：3 已证实 / 1 待核验，供应商层拿到「元气森林(广东)饮料有限公司」，品牌层因官网未验真而**显式空白**，没有编造。
- 三无输入（无 SC、无标准号、无厂名）：0 已证实，`compat.found=false`，前端走「查不到」态。
- 已修：SERP 缓存错存去标签文本导致百度解析恒为 0；`html_to_text` 先剥标签后反转义使 `&lt;p&gt;` 复活成标签字面量；配料首项「水」被长度过滤吞掉；厂址被前一个标签字段吃掉。

## 2026-11-21 16:40–16:55 · 溯源准确性修复：把「有结果」和「结果对」分开

起因是自查发现四处会产出**错误断言**的缺陷。溯源这种东西，错一条比空十条更糟，评测口径定为「错误断言数 / 空缺率 / 命中率」，错误断言目标 0。

| 缺陷 | 实测证据 | 修法 |
|---|---|---|
| 标准号子串误配 | 查 `GB/T 1354`（大米）首条是《电气绝缘用薄膜》，查 `GB/T 1355`（小麦粉）是《汽车多楔带》，查 `GB/T 10781.1` 被 `GB/T 10781.14` 顶掉 | `select_standard()` 只接受编号本体精确相等（去年份、去空白、统一连字符），子串命中写进 `near_misses` 不采信 |
| 旧版「废止」安到本品头上 | 包装只印 `GB 7101`，系统只有 2003 废止版，初版直接给本品亮警告 | 包装没印年份 → `edition_certain=False`，只展示「该编号的收录记录」+ caveat，flag 降 `unverified` 并补 gap；只有印着 `GB 7101-2003` 时才允许 `flag=warn` |
| 跨行业同名企业并列成链 | 海天搜索命中注塑机厂「海天集团 Haitian Group」，其摘要写「饮料包装 PET 成型方案」，靠摘要食品词判行业必然误判 | `_entity_hits()` 双闸：`NONFOOD_HINT` 剔除；**包装已给生产主体时，名称对不上的一律不进链**，只进 gap 标「同名关联企业，关系未核实」 |
| 原料先验表冒充证据 | 12 条「赤藓糖醇主产山东」之类常识全部无来源，却计入 provenance | 原料层改 `unverified`，先验表移出证据链，单独进 `common_sense`（`verified=False`、空 source），节点标题写明「品类常识（未核实）」并加 gap |

连带修掉一个字段截断 bug：`FIELD_CUT` 漏了「产品标准号/生产许可/净含量」等边界词，生产商被抽成「达能（中国）食品饮料有限公司 产品标准号：GB 7101」，导致主体比对恒为 False。

回归（26 条离线测试全过 + 联网实跑）：

- 大米 → `GB/T1354-2018《大米》`；小麦粉 → `GB/T1355-2021《小麦粉》`；白酒 → `GB/T10781.1-2021《浓香型白酒》` 与 2006 旧版并列展示。**跨行业残留 3/3 → 0**。
- `GB 7101` 无年份：`flag=unverified` + 「本品执行版本未核验」gap，不再假报警；`GB 7101-2003` 带年份：`flag=warn`，废止状态正确归属本品。
- 海天：只保留「佛山市海天调味食品股份有限公司」（与包装主体一致），注塑机海天全部进 gap；元气森林：北京/广东关联公司进 gap，包装「（安徽）」主体在 factory 节点 `proven`。
- 原料：`raw_prior_table` 在证据链出现次数 → 0，`common_sense` 全部 `verified=False`。

仍未做：**没有真实包装照片真值集，所以给不出准确率百分比**。上面所有数字是「已知错误是否被消除」的回归，不是统计意义上的准确率。下一步需要 10 个商品的真实照片，人工核对生产主体/厂址/标准号三个字段的真值再评分。
